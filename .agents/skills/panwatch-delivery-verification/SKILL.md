# 交付验证

## 建立验证范围

读取项目 [AGENTS](../../../AGENTS.md)、[README](../../../README.md) 的实际命令、相关 spec/plan 与本次修改。确定交付版本：优先使用真实 commit，存在未提交内容时同时注明工作区状态。

逐项对应验收条件与受影响行为，选择足以判断结果的验证。自动检查、人工操作、真实外部调用与模拟分别标记，不用模拟结果代替真实集成验收。

需要完整本地隔离实服验收、脱敏证据报告或 PR 附件交付时，使用 [panwatch-local-delivery](../panwatch-local-delivery/SKILL.md)；本技能负责验收映射与结论，不重复那套环境流程。

## 执行与证据

- 按实际项目执行必要检查、测试和构建：

```bash
make check
make test
pnpm --dir frontend exec vitest run
make verify                 # 聚合检查；仍不等于人工验收
make build VERSION=<version>  # 仅在需要验证镜像产物时
```

- 用户可见行为变化时，检查中英文 i18n、亮色/深色、桌面/移动、键盘焦点和共享 UI 约定；按 [统一 UI 约定](../../../frontend/UI_GUIDELINES.zh-CN.md) 执行前端检查。
- 验证产物时检查其可安装、加载、启动或页面行为，而非只确认文件存在。
- 任务未配置、环境缺失、无业务实现或无测试时明确写“未执行”及原因，不创建成功占位命令。依赖未安装、`.venv` 或 `frontend/node_modules` 不存在时，记录未执行而不是伪造通过。预期有测试却意外发现零用例时记为 `FAIL`。
- 命令执行后失败记为 `FAIL`，保留命令、退出码与关键观察；不能改记为未执行。记录原失败及后续修复复验，不抹去历史。
- 证据包含版本、环境、日期、命令/操作、实际结果和位置，避免记录密钥、私人持仓或敏感业务数据。先检查旧证据是否覆盖当前版本，不能直接继承旧结论。
- 选择与改动风险相称的验证。必要检查通过后，无新增改动或未决风险时不无目的重复扩大测试。
- 代码改变或多任务集成后，对受影响的条件重新验证。涉及外部副作用的操作遵循已有授权，未获授权的部分记录为未执行。
- 真实 AI 模型、行情供应商、通知送达和外部账号操作分别记录；模拟发送、HTTP 200、进程存活或数据库存在不能单独证明业务验收通过。

## 结果落点

普通任务在原 spec/实施记录或 PR 中维护验收映射；大型任务按需使用 [追溯与归档样板](../../../docs/templates/trace-and-archive.md)。人工操作步骤引用 [smoke 清单](../../../docs/tests/smoke.md)。更新相关索引的真实状态，不重复维护完整报告。

最小记录字段：验收条件、检查方式、对应版本、实际观察、`PASS`/`FAIL`/`未执行`、证据、未解决项与补齐条件。没有明确验收条件时先列验证范围和限制，不自行编造用户已经接受的标准。

交付结论分别说明实现状态、评审状态、自动检查、人工接受、合并与发布。存在关键 `FAIL` 或未验证的必要条件时说明尚未满足交付条件；仅报告已证实的完成范围，不宣布整体验收通过。归档遵循 [开发规范](../../../docs/standards/development.md)，本技能不自动授予合并或发布权限。
