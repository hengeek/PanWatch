## 用户与问题

现有 macOS 桌面端围绕持仓与自选展开：左侧分组、中间表格、右侧摘要详情，适合盯住已知股票，但缺少一条从「看全市场 → 发现标的 → 进入完整个股页研究」的路径。

用户提供的原型展示了指数、热榜、行业概念、涨跌分布、涨跌停、龙虎榜、资金流向、T+0 ETF 八类行情信息。当前后端只覆盖其中的一部分；若直接照搬页面，会把缺失数据伪装成已交付能力。本需求先把页面结构、数据边界和空态确定下来，再按数据可用性分阶段实现。

## 目标与范围

本次目标：

- 在现有 macOS 主窗口内吸收行情能力，不新增独立窗口形态。
- 新增「行情中心」页面：指数、行业概念、热榜、市场宽度、资金与席位四组信息。
- 新增「个股详情」整页：行情头部、日/周/月 K + 成交量 + MACD、概览/板块/资金/龙虎榜/热度/涨停基因标签、右侧指标与笔记区。
- 对每个数据模块标注「可用 / 部分可用 / 待接入」，缺数据时展示明确空态，不显示伪造数值。
- 分时图在真实分钟数据接入前保持禁用状态，不用日线或随机曲线代替。

明确不做：

- 交易下单、开户导流、券商合作入口。
- 社区、人气互动、关注用户等社交能力。
- 付费行情采购、分钟数据供应商签约（需单独决策与授权）。
- 在本页生成新的 AI 投资建议；只复用已有报告、助手和研究资料。
- 未确认数据源前实现涨跌分布、涨跌停、人气榜、F10、研究笔记等服务端能力。

## 用户行为与规则

### 导航与入口

- 拟在顶部导航增加一级入口「行情」，与「盯盘 / 消息 / 组合」并列；该改动会改变现有主窗口导航结构，需用户确认（见 D1）。
- 行情中心默认展示「市场总览」；左侧分类可切换指数、热榜、行业概念、涨跌分布、涨跌停、龙虎榜、资金流向、T+0 ETF。
- 点击指数卡片、热榜行、行业领涨股、龙虎榜行，进入个股详情；返回时保留行情中心的分类、滚动位置和筛选条件。
- 个股详情左侧保留自选股列表，切换股票不离开详情页；右栏随股票切换整体刷新。

### 数据状态与空态

所有行情区域必须显示数据状态，而不是只显示数值：

| 状态 | 含义 | 展示 |
|---|---|---|
| 可用 | 当前市场、当前时段有真实数据 | 绿色状态点 / 「实时 · 可用」 |
| 部分可用 | 只有部分市场、部分字段或非实时快照 | 琥珀色状态点 / 说明缺什么 |
| 待接入 | 后端尚无结构化数据或数据源未确认 | 灰色状态点 / 「待接入」空态 |
| 过期 | 有数据但报价日期不是当前交易日 | 显示报价日期与「延时」 |
| 失败 | 请求失败或数据源不可用 | 明确错误文案与重试入口，不保留旧值为最新 |

规则：

- 生产界面不得出现随机数、写死的示例行情或「看起来像实时」的占位曲线。
- 设计稿中的数值仅用于版式评审，已在原型中以「示意」「待接入」标注；实现时不得复用这些数字。
- 涨跌分布、涨跌停、资金流向、龙虎榜等日频数据必须显示对应交易日，不能把收盘数据标成盘中实时。
- 缺失字段显示「—」并说明原因；不把 0 当作缺失值。
- 行情时间、报告生成时间、AI 摘要时间分别展示，不能互相替代。

### 行情中心

- 摘要栏展示上证、深证、创业板、恒生、纳斯达克五个指数的点位、涨跌幅与市场状态；数据来自 `/api/market/indices`。
- 指数卡片展示名称、代码、点位、涨跌额/幅与近 20 日 sparkline；sparkline 来自真实日线，不使用随机曲线。
- 行业概念在 A 股使用真实行业板块；港股/美股目前只有合成主题桶，必须标注「合成主题」，不能冒充行业分类。
- 热榜首期只提供「成交额榜 / 涨幅榜」；「人气榜」需要新数据源，未接入前不得使用该名称（见 D2）。
- 涨跌分布、涨跌停在数据源未确认前只保留版式与空态，不展示具体家数（见 D3）。
- 龙虎榜、资金流向、T+0 ETF 在结构化 API 未交付前显示「待接入」，不调用 AI 工具结果冒充行情。
- 底部固定显示连接状态、数据源、行情延时与免责声明。

### 个股详情

- 头部展示名称、代码、板块标签、现价、涨跌额/幅、加自选、设提醒、问助手；报价缺失或过期时头部必须可见地标注。
- 周期标签：分时（待接入）、日 K、周 K、月 K；日/周/月来自现有 `/api/klines`，周/月由日线聚合。
- 图表包含蜡烛、MA5/MA10/MA20、成交量、MACD；指标由真实 K 线计算，不请求 AI。
- 分时标签在分钟数据接入前禁用，并显示「待接入真实分钟行情」；不得用日线插值或模拟曲线占位。
- 概览标签展示行情字段、估值字段和 52 周区间；只有后端返回或可由真实日线计算时才显示。
- 资金、龙虎榜、热度、涨停基因标签在数据未接入时显示空态；热度不能使用编辑手填数字。
- 「公司简介 / F10」「研究笔记」当前无数据与存储能力，首期隐藏或标注待接入，不作为已交付功能（见 D7）。

### 窗口与信息密度

- 设计稿沿用现有 macOS 设计画布 1586×992；实际窗口为 1180×780，落地时按比例收敛并重新验收密度。
- 行情中心为 264px 侧栏 + 主区；个股详情为 220px 自选栏 + 916px 主区 + 450px 右栏。1180 宽度下建议改为约 15% / 58% / 27%，并允许右栏折叠。
- 1180×780 下不得出现横向滚动；表格列可压缩，右栏卡片可纵向滚动。

| AC-13 | 断网或数据源超时 | 保留的区域标注过期/失败与最后更新时间；不把旧值显示为实时；提供重试 | 人工 + 集成测试 |

## 兼容性、风险与未决问题

- 现有主窗口导航、1180×780 尺寸、迷你窗和菜单栏共用同一套状态；新增行情页不能破坏现有盯盘路径。
- 桌面 `Quote` 类型过窄，扩展字段时需同步 Swift 桥接、响应校验与旧版本兼容。
- 非官方行情接口存在限流、字段漂移和合规风险；必须缓存、超时、失败降级并显示数据时间。
- 全市场涨跌家数与涨跌停需要一致快照；分时/日频数据不能混在同一时间口径里。
- 1180×780 下三栏密度需要单独验收；设计稿的 1586×992 画布不能直接当作实现尺寸。
- 龙虎榜与资金流字段在包内标注「待实抓校准」，上线前必须用真实响应核对，不得按猜测字段展示。
- 第三方原型仅作参考；当前设计稿使用 PanWatch 自有绿色 token、字体和布局，未复制第三方 logo、皮肤或开户素材。
